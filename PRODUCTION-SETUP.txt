10. SETUP AUTOMATED BACKUPS
----------------------------
cat > ~/backup-databases.sh << 'EOF'
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR=~/backups
mkdir -p $BACKUP_DIR

docker exec postgres_prod pg_dump -U quidpath_user quidpath_db > $BACKUP_DIR/backend_$DATE.sql
docker exec postgres_billing_prod pg_dump -U billing_user billing_prod > $BACKUP_DIR/billing_$DATE.sql
docker exec tazama_postgres pg_dump -U tazama_user tazama_db > $BACKUP_DIR/tazama_$DATE.sql

# Keep only last 7 days
find $BACKUP_DIR -name "*.sql" -mtime +7 -delete
EOF

chmod +x ~/backup-databases.sh

# Add to crontab
crontab -e
# Add: 0 2 * * * ~/backup-databases.sh

TROUBLESHOOTING
===============

Service not starting:
docker logs <container-name>
docker exec <container-name> env | grep -E "JWT|SECRET|DATABASE"

JWT auth failing:
docker exec django-backend env | grep JWT_SECRET_KEY
docker exec billing-backend env | grep JWT_SECRET_KEY
docker exec tazama-ai-backend env | grep JWT_SECRET_KEY
# All three must match!

Webhook not working:
docker logs django-backend | grep webhook
docker logs billing-backend | grep webhook
docker exec billing-backend ping django-backend

ZERO-DOWNTIME UPDATES
=====================

To update without downtime:

1. Pull latest code:
cd ~/quidpath-deployment/<service>
git pull origin main

2. Build new image:
docker compose build --no-cache

3. Rolling restart:
docker compose up -d --no-deps --build <service-name>

4. Run migrations:
docker exec <container-name> python manage.py migrate

5. Verify:
curl https://<domain>/health/

SUPPORT
=======

Check logs first:
docker logs <container-name> --tail 100

Common issues:
1. JWT_SECRET_KEY mismatch - verify all three services have same value
2. Webhook secret mismatch - verify backend and billing have same value
3. Service API key mismatch - verify keys match between services
4. Database connection - check DATABASE_URL format
5. SSL certificate expired - run: sudo certbot renew

SECURITY CHECKLIST
==================

- All secrets are strong (32+ characters)
- JWT_SECRET_KEY is same across all services
- BILLING_WEBHOOK_SECRET matches in backend and billing
- Service API keys match between services
- DEBUG=False in all .env files
- Database passwords are unique and strong
- SSL certificates are valid
- Firewall configured (ports 80, 443, 22 only)
- Regular backups configured
- Certbot auto-renewal enabled
